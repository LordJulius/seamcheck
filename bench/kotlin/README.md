How okhttp's Kotlin went into a CodeQL database for `bench/vs_codeql.py`
(CodeQL extracts Kotlin only from a compile; no Gradle / Android SDK needed):

1. Jars from Maven Central: okio-jvm 3.18.2, conscrypt-openjdk-uber 2.5.2,
   bcprov / bctls-jdk18on 1.78.1, openjsse 1.1.14, animal-sniffer-annotations
   1.24, jetbrains annotations 24.1.0, android 4.1.1.4.
2. Two stubs: `CONST_VERSION` (from `kotlinTemplates/-InternalVersion.kt`) and
   `IDNA_MAPPING_TABLE` (generated by the build) as an empty IdnaMappingTable.
3. kotlinc 2.0.21 over `okhttp/src/commonJvmAndroid` and `okhttp/src/jvmMain`
   (less `internal/graal`), as two fragments:
   `-Xmulti-platform -Xfragments=common,jvm -Xfragment-refines=jvm:common
   -Xfragment-sources=... -opt-in=okhttp3.internal.OkHttpInternalApi`.
4. `codeql database create DB --language=java --source-root=okhttp --command=build.sh`,
   then `codeql query run -d DB bench/codeql/java/calls.ql` and `bqrs decode --format=csv`,
   then `python3 bench/vs_codeql.py okhttp --csv calls.csv`.
